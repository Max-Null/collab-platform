01这次调研怎么做的

起点是找「团队模式 / 多代理」的参考。作者 xingtu1996（行途，一线技术经理仍在写代码） 有十几个公开仓，其中五个直接 git clone 下来读了原文。

一个方法上的选择：GitHub 页面直连超时，但 api.github.com 与 git clone 都通。 所以走的是「拉仓库读文件」，而不是「抓页面读渲染结果」——读到的是一手原文，不是二手介绍。

另一个是先定位再深读：我们平台是「闸门 + 账本」，他们多数仓是「多代理编排器」。 位置不同，所以先花一轮把仓库矩阵摸清，再挑与「闸门/账本/治理/记忆」最近的九块读。

02九轮读了什么

每轮一个主题，从「多代理怎么干活」一路读到「静默失效怎么防」。

第 1 轮
仓库矩阵与多代理核心资产
编排入口的六条铁律、子代理的输出契约、三形态选型
第 2 轮
治理四件套
「规则是愿望，hook 才是墙」· 安全三条件 · 复制即第二份 SSoT
第 3 轮
常驻税与验证成本
loops win where verification is cheap —— 解释了我们的观察期为什么跑不动
第 4 轮
常驻配置的减法治理
膨胀的真代价是「模型选择性忽略」，不是 token
第 5 轮
会话与记忆
记忆缺一条毕业路径：记录 → 记忆 → 策略
第 6 轮
对抗审查
交叉验证 = ≥2 个视角独立发现 —— 一种不需要人的置信度信号
第 7 轮
隐形契约审计
唯一一份与我们题目相同的材料：专讲静默失效
第 8 轮
可证伪闸门
结论只允许 为真 / 为假 / 条件成立（注明已知缺口）
第 9 轮
实践案例

03最有价值的几条判据

这些都不是「他们说我们该怎么做」，而是读的时候能立刻对上我们某个具体缺口的那些。

验证成本决定循环能不能转
「loops win where verification is cheap」。我们的观察期要人逐条回写反应，那是高成本验证 —— 这是成本问题，不是意愿问题，所以「再强调一次请回写」解不开。
→ 观察期加「看过」分母（已落地）
规则是愿望，hook 才是墙
策略就是那堵墙，而处置级别就是墙的高度：级别 1 不是墙（愿望），级别 3 才是。于是「观察期」有了另一层说法 —— 把愿望升级成墙的过程。
→ 设计 §3.7
一个标签若能对应两种截然不同的现实，它就不是合格的探针
他们的例子：miss 同时表示「查了没命中」与「根本没启用」。我们缺 off 这一态 —— 「策略被停用」和「跑了但没事件」现在长得一样。
→ T11（与 T4 合成一条线）
结论只允许三态，而我们的第三态是错的
他们要的三态是 为真 / 为假 / 条件成立（注明已知缺口）。我们的 error 说的是「这次没做成」（过程），缺的是「结论对但有前提」（结论）。
→ T13 · 设计 §3.11 三
删掉它会犯错吗？不会 → 删 / 沉降
把问题从「它有没有用」换成「没有它会怎样」—— 后者人答得出来，前者常常答不出来。与「可检验」「可执行」合成入口检查三条。
→ 设计 §3.10
膨胀的真代价不是 token，是「模型会选择性忽略」
选择性忽略不报错：模型照样自信地给出判断，只是有些规则它已经不再真的在看了。我们的记忆治理四条触发管的全是「哪一条该退场」，没有一条管「一共能装多少条」。
→ 设计 §3.10
交叉验证：一种不需要人的置信度信号
≥2 个独立视角发现同一件事 —— 至少证明它不是某个视角的幻觉。⚠️ 但它证明的不是「判断正确」：一条判据可以稳定地、被两个视角一致地判错。
→ T9
加一条新策略应当是「纯新增」
他们把一个抽象层的验收项定成「原有组件零改动」—— 把「没破坏现状」从承诺变成机器可查的验收项。若加策略需要改管道，那说明缺的是扩展点。
→ 设计 §3.11 一

04落地情况

48 条结论里有 35 条有落点。回指一遍才知道 —— 这件事不做，半年后会以为读了九轮什么都没改。

35
/ 48 有落点
改了代码 —— 7 条 （带提交）
改了文档 —— 14 条 （设计 / 方案章节）
进了待办 —— 14 条 （T1–T14）
只是对照 —— 13 条 （已在这么做，属确认）

那 13 条「只是对照」不是浪费

它们多数是「我们已经在这么做」的独立佐证。最典型的一条：「完成判定认落盘凭证，不认模型自述」 —— 四个不相干的场景各撞了一遍（他们的定时任务、他们的对抗审查、他们案例 003、我们自己的 error 三态）。四个项目各撞一遍的坑，比任何一家的最佳实践都更值得当判据。

回指过程揪出四条「以为落了、其实没落」

以为落了实际处置
「删掉它会犯错吗」只在调研笔记里补进设计 §3.10
「无拦截价值的沉淀不必反哺」只在调研笔记里补进设计 §3.10
「待拍板必须带默认值」设计 §六 那 5 条没写默认值逐条补上
「五类靶」只在调研笔记里补进设计 §3.11 五
原因是一样的：写调研笔记的时候，「对我们的意义」这一段写得越顺，越容易让人以为写完就等于落了。 而「落」是指它出现在会被执行的地方 —— 设计文档的判据里、待办表里、代码里。 这正是第 7 轮那条「注释记的是写那一刻的意图」的同一个机制

05明确不采纳的

读别人的东西，说不采纳比说采纳更需要理由。

他们的做法为什么不采纳
并行 ≤3（理由：人的 review 带宽）那是内容生产场景的带宽约束。平台的并发由事件驱动，按事件到达走，不设人为上限
深度档 / Flash 档的模型分档平台不替策略选模型 —— 用哪家是配置（LLM_* 环境变量），不是编排决策
「不做跨 Agent 记忆同步总线」那是在没有平台的前提下做的减法。GM 的长期记忆正是要解决跨会话，只是放在判断记录这个可查证的地基上
编排模式映射表 / 单篇 DAG他们是编排器（多代理怎么分工），我们是闸门与账本（干完之后谁判断、依据留不留）。平台不做编排

06下一步

九轮到最后，边际收益明显下降了。剩下没读的主要是 40 个场景模板（测试金字塔、部署 SOP、工单回复这类 「照着做」的清单），而我们的平台本身不做那些场景。

更值的是回去把三条方案级的事谈掉：hold_merge 与级别 3 的动作（连带「退出 / 幂等 / 回滚」三条件， 我们回滚那条是空的）、「数据够了算够」的判据（它卡着控制台「待评估」那一屏）、 以及阶段二 / 三的排期。
