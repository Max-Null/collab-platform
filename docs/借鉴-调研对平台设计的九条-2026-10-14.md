# 借鉴 · 调研对平台设计的九条（2026-10-14）

> 前一篇是**追踪**（[每条结论去了哪儿](调研落地对照-2026-10-14.md)），这一篇是**归纳**（哪些该进设计）。
> 九轮材料里，真正能改设计的分成三层：**改结构的三条 / 改概念的三条 / 改纪律的三条**。

---

## 先说结论

**最值得借的不是某条判据，是三个结构性的东西**：

| # | 借什么 | 一句话 |
|---|---|---|
| **L1-1** | **平台有一条演进链，而它中间那一环是空的** | 判断记录 → **记忆** → 策略。目标：错只犯一次 |
| **L1-2** | **每一维都该是「插进去」的，不是「改开膛」** | 加策略 = 一个文件 + 装配一行；需要改管道，说明缺的是扩展点 |
| **L1-3** | **平台的题目有名字了：静默失效** | 它给了一条可直接当验收口径的判据 |

---

# L1 · 改结构

## L1-1 演进链：判断记录 → 记忆 → 策略

**来源（两处独立）**：

- 「**规则是愿望，hook 才是墙**」—— 治理四件套
- 「**纠偏即时机械化**：高频纠偏 → 沉淀为铁律/清单，**错只犯一次**」+ 循环工程那条「坑 → BCI → Gate → 自动拦截」

```
判断记录  →  记忆  →  策略
（每次判定）  （归纳出的模式）  （固化成判据，机械执行）
  事实层        模式层           墙
```

**为什么这是结构性的，而不是"再加一个模块"**：

平台现在只有**两端**：策略（判据）与判断记录（事实）。**中间那一层是空的。**

而空着的结果是具体的：**同一个坑要靠同一批人反复判断** —— 每次都是"重新判断"，没有"记住"。GM 现在判断时不读自己的历史，所以「上次这条被判错了」对它不存在。

**一句话目标**：**错只犯一次。**

**落地约束**（已写进设计 §3.10）：记忆不是"背景知识库"，它有**毕业路径** —— 一条反复被验证、且影响过的判断被人采纳的记忆，就该提议**升级为策略**。

> ⚠️ 这与「双轨」的关系要想清楚：双轨改**已有**判据（影响现有判断，评审成本高）；**升级是新增**判据（只是多一道闸，评审成本低）。**所以升级可以走得比双轨快。**

## L1-2 每一维都该是「插进去」的

**来源**：案例 004 的验收项 —— **「新抽象层存在，且原有组件零改动」**。

它把「没破坏现状」从一句承诺变成了**机器可查的验收项**。

**照到平台上，每一维都该满足这个**：

| 加什么 | 应该是 |
|---|---|
| 一条策略 | 一个文件 + 装配里一行 |
| 一个事件源 | 实现 `EventSource` 接口 |
| 一个动作 | 实现 `ActionRunner` 接口 |
| 一个出口 | 复用 `wiring.ts` 的装配 |

**判据**：**若加一个新东西需要修改已有的管道代码 —— 那说明缺的是一个扩展点，该补扩展点，而不是让每加一次就动一次管道。**

**它已经照出三个缺口**：

| 缺口 | 现状 | 待办 |
|---|---|---|
| **`trigger`** | `Policy` 接口只有 `evaluate` 与 `disposal`；**管道对每个事件跑每一条策略** | T7 |
| **`notFor`** | 策略没说「**不**负责判断什么」，职责边界没有写下来 | T8 |
| **冲突仲裁** | 两条策略意见相反时，实际行为是 `pipeline.ts` 里的「取级别最高」—— **是实现细节，不是规则** | 设计 §3.11 二 |

**第二条（触发）在规模上会立刻暴露**：两条策略时无所谓，十条策略时成本就是「策略数 × 事件数」，而其中大量事件根本不在那条策略的覆盖范围内。

## L1-3 平台的题目：静默失效

**来源**：第七轮那份隐形契约审计 —— **九轮材料里唯一一份与我们题目完全相同的**。

> **算法很少错；错的是那些「没人当成契约」的东西** —— 键、缓存、落盘文件、派生副本、定义位置。
> `if` 写反会崩，测试会红。但「缓存键少放一个因子」不会崩 —— **它只是安静地给你旧结果**。

**为什么这是结构性的**：

我们一直在用各种说法描述平台在防什么 —— 「沉默承担不了通过」「评估失败不等于通过」「没人看过 ≠ 无视」「平台看不到 ≠ 这次没问题」。**这些是同一条判据的五个化身，但它一直没有名字。**

**「静默失效」就是那个名字。** 有了名字之后，很多设计选择从「我们觉得应该这样」变成「这是针对某类失效的机制」。

**它还顺带给了一条可直接当验收口径的判据**：

> **一个标签如果可能对应两种截然不同的现实，它就不是个合格的探针。**

**用法**：平台输出里的每一个标签，逐个问一遍「**它可能同时意味着两件事吗**」。已经问出结果的三处：

| 标签 | 它同时意味着 | 处置 |
|---|---|---|
| `miss` | 查了没命中 / 根本没启用 | 补 `off`（T11） |
| `评估次数` | 跑过 N 次 / N 条策略各跑一次 | 运行图上写清了，但要盯住 |
| `ignored` | 看了但没管 / **根本没人看过** | 已拆出 `reviewed`（`604b25c`） |

# L2 · 改概念

## L2-1 「判断」该长出前提

**来源**：第八轮的可证伪闸门 —— 结论只允许 **为真 / 为假 / 条件成立（注明已知缺口）** 三态。

**我们的 `error` 与它的「条件成立」不是一个东西**：

| | 说的是 | 性质 |
|---|---|---|
| 我们的 `error` | 这次**没做成**（取不到数、模型调不通） | **过程**的失败 |
| 它的「条件成立」 | **结论对，但有前提** | **结论**的限定 |

**举例**：GM 判「改动与声称不符」，但**只在描述写得过于简略时成立**。现在它只能表达成无条件的 `hit` —— **而它的前提没有地方放**。于是人只能就「对/不对」表态，**而这个表态对一条条件结论来说是没有意义的**。

「判断」这个概念因此从「**是 / 否**」变成「**在什么前提下，是什么**」。

## L2-2 策略之间不是孤立的

两个来源各给了一半：

| 来源 | 说的是 | 平台的空白 |
|---|---|---|
| 案例 004 的 Team 契约四要素含「**冲突仲裁**」 | 两条策略意见相反时谁说了算 | 现在藏在代码里 |
| 第六轮的「**交叉验证 = ≥2 视角独立发现**」 | 多条策略指向同一处 = 更高的先验置信度 | 现在策略各判各的，输出不互相引用 |

**第二条需要一个共同锚**。我们**已经有一个**：`evidence` 里的 `changed_file`（含具体路径）。**两条策略命中了同一个文件**，就是一个可算的、不需要人的重合信号。

⚠️ 边界：它证明的是「**不是幻觉**」，不是「**判断正确**」—— 一条判据可以稳定地、被两个视角一致地判错。所以它只能决定「**哪些判断值得优先给人看**」，不能替代人的反应。

## L2-3 置信度有两种来源，平台只用了成本高的那种

| 来源 | 成本 | 现状 |
|---|---|---|
| **人回写反应**（地面真值） | 高 —— **这正是观察期跑不动的原因** | 唯一的判据来源 |
| **机制内部一致性**（交叉验证 / 判据稳定性） | 零人力 | 观察到过现象，但**当成缺陷记了，没当成信号用** |

**来源**：第三轮那句「**loops win where verification is cheap**」—— 循环取胜的前提是验证成本低廉。

**照到设计上**：「数据够了算够」这个判据（T2）不该只依赖「人回写了多少次」。零成本的那条信号现在是可以取的，只是没人在取。

# 不能借的，以及一种容易借错的

## 明确不能借

| 他们的做法 | 为什么不借 |
|---|---|
| 编排模式映射表 / 单篇 DAG | 他们是**编排器**（多代理怎么分工），我们是**闸门与账本**（干完之后谁判断、依据留不留）。**平台不做编排** |
| 并行 ≤3 | 那是**内容生产**里**人的** review 带宽；平台的并发按事件到达走 |
| 深度档 / Flash 档的模型分档 | 用哪家是配置（`LLM_*`），不是设计决策 |
| 「不做跨 Agent 记忆同步总线」 | 那是在**没有平台**时的减法。GM 的记忆正是要解决跨会话，只是放在**判断记录**这个可查证的地基上 |

## ⚠️ 容易借错的一种：形式像、理由不同

**cavecrew 的输出契约**（investigator / builder / reviewer 各自固定的输出格式）看起来和我们的判断记录、评论格式很像。

**但理由完全不同**：

| | 它为什么定契约 | 我们为什么定格式 |
|---|---|---|
| cavecrew | **省 token** —— 子代理输出原样注入主上下文，压到 1/3 就是 20 次委派能不能跑完的差别 | **可追溯** —— 结论要能走回来源，依据要分四类 |

**形式可以借，理由不能借。** 若照它的理由去优化我们的格式（压得更短、去掉类型标注），**恰好会把可追溯性压掉** —— 而那才是我们定格式的原因。

# 一句话总结

九轮读下来，**最有用的一条不是他们说的某句话，而是一个反复出现的现象**：

> **同一条判据，在不同的项目里被独立地撞了一遍又一遍。**

「认落盘凭证不认自述」撞了四次；「标签不能有两种含义」撞了三次；「沉默不等于通过」贯穿全部九轮。

**这说明它们不是某个人的经验之谈，而是这类系统的结构性坑** —— 而当我们要判断一个设计对不对时，**「有没有独立来源撞过它」比「有没有权威说过它」更值得信赖。**
